# SOS alerts

SOS is a helper for a paired patient device or patient login to alert linked caregivers. It does not contact emergency services. In an emergency, call 112 yourself. SOS requires the phone to be powered on, online, and in the person's hands. It is not a replacement for medical care or emergency services.

The SOS send flow is silent. It has no automatic voice, speech synthesis, sounds, or vibration. To prevent accidental triggers, the user presses and holds the SOS button for 3 seconds. Once the hold finishes, a full-screen countdown runs from 5 to 1 showing "Sending alert in {n}" alongside a prominent full-width Cancel button. If the person switches to another tab during the countdown, the alert still sends automatically at 5 seconds; switching to another tab does not stop the alert; only Cancel does. If the phone screen locks or the app is backgrounded for a long time, the browser can pause the page and the alert may wait until the person unlocks it.

When the countdown reaches 0, the alert is sent automatically. The confirmation screen displays only a large check icon, "Alert sent.", and a Back button without sound or next-step instructions. If sending fails due to network or server issues, the page displays "Sending..." and silently retries every 5 seconds for up to 2 minutes using an idempotent request key. If after 2 minutes the alert cannot be delivered, "Could not send. Try again." is displayed.

The "Include my location" checkbox sits above the hold button (enabled by default and remembered per device in localStorage). When checked, geolocation is requested at the start of the 5-second countdown with a 4-second timeout. If coordinates arrive before 0, the alert is created with location immediately. If coordinates arrive after the initial alert is sent (within 2 minutes), they are attached via `PATCH /sos/alerts/<id>/location`. That endpoint allows exactly one successful patch per alert from the session that created it (validated via a one-way owner session hash) and is rate-limited to 3 requests per alert.

The backend stores alerts in each patient's `alerts.json` file. A real alert may email every linked caregiver when SMTP is configured; email failures do not prevent alert creation, and late-arriving location patches send no second email. Test alerts stay local and never send email. Locations are optional per alert, visible only to linked caregivers, removed after 30 days, and alerts are deleted after 90 days. Alerts are limited to one per minute and five per hour per session.

Cross-device delivery requires both devices to reach the same hosted backend over HTTPS. Browser geolocation requires HTTPS or localhost; if permission is denied or on an insecure origin, the alert is sent without location. Browser notifications require the caregiver's alert page or app tab to remain open and notification permission to be enabled. SOS is a helper for linked caregivers, not emergency services, and does not call or test emergency numbers.
